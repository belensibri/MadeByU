# MadeByU · Correspondencia entre prototipo y proyecto final

| Requisito del proyecto final | Qué muestra este prototipo | Documentación que debe acompañarlo |
|---|---|---|
| Definición del ecommerce | Nombre, público, catálogo, propuesta de personalización | Fase 1: descripción, B2C, dominio, hosting, plataforma, propuesta de valor y buyer persona |
| Home | Pantalla inicial con CTA crear / explorar, precios desde $9.99 | Wireframe inicial y justificación de decisiones |
| Categoría | Navegación de 3 pilares, filtros por color y tamaño | Arquitectura SEO corregida y keyword research |
| Producto | Composición de flores, cantidad, presentación, precio y opciones | Wireframe de producto |
| Carrito / pasarela | Añadir/eliminar, total, retiro/domicilio, pago simulado | Wireframes y elección de pasarela para producción |
| Confirmación | Referencia DEMO y resumen sin pedido real | Wireframe de confirmación |
| Investigación UX | Interfaz diseñada para necesidades encontradas en cinco cuestionarios | Evidencia de cuestionarios originales y desk research; entrevistas a profundidad adicionales si es viable |
| Pruebas UX | `#/pruebas`, tareas, cronómetro, observaciones y exportación | Resultados reales con participantes y mejoras documentadas |
| SEO | Tres pilares y filtros independientes de URLs | Plan SEO, titles, meta descriptions, enlazado y optimización ecommerce |
| Marketing digital | No implementado en prototipo técnico | Plan de canales, objetivos, presupuesto, estrategia orgánica y proyección de visitas, conversiones, ventas, ticket y ROAS |

## Flujo de navegación
`Logo → Home` / `3 pilares → Catálogo → Detalle → Carrito → Checkout → Confirmación DEMO`.

Ruta alternativa: `Home / cualquier vista → Crea tu ramo → Personalizador → Carrito → Checkout → Confirmación DEMO`.

## Cómo se investigó el producto
Las decisiones de personalización, precio visible, inspiración, retiro / domicilio y medios de confianza provienen de **cinco respuestas abiertas de exploración inicial**. Este proyecto no incorpora resultados de pruebas UX anteriores; se diseñó específicamente para realizarlas ahora.

## Precauciones para la defensa
- Explicar que **el proyecto final no obliga a desarrollar un ecommerce funcional**; este código complementa la evidencia de UX.
- Aclarar que precios, costos por tallo, entrega y disponibilidad están pendientes de validación.
- No presentar como reales las ilustraciones, reseñas o confirmaciones ficticias.
- Evitar confundir la funcionalidad de prueba con integración de Wompi u otra pasarela.
